# Vue + Java 全栈开发面试题（详细版）

> 适用方向：中高级全栈开发（前端 Vue3 + 后端 Java/Spring Boot + 数据库 + 微服务 + DevOps）
> 
> 使用建议：
> 1. 先按模块刷一遍，建立“知识地图”；
> 2. 再按项目场景组织答案（你做过什么、怎么做、结果如何）；
> 3. 每题建议准备“60 秒版本”和“3 分钟版本”两套话术。

## 一、Vue 核心与工程化

### 1. Vue2 和 Vue3 的核心差异是什么？为什么 Vue3 性能更好？
**面试官期待点**
- 能说清响应式实现差异（`Object.defineProperty` vs `Proxy`）
- 能解释编译优化（静态提升、Patch Flag、Fragment）
- 能结合项目说明“为什么快、快在哪里”

**参考答案**
Vue2 使用 `Object.defineProperty` 劫持对象属性，缺点是对新增/删除属性、数组部分操作支持不够直接；Vue3 使用 `Proxy` 拦截整个对象，天然支持更多操作，响应式边界更清晰。

Vue3 性能提升主要来自三层：
1. **响应式层**：`Proxy` + 精细依赖收集，减少无效更新。
2. **编译层**：静态节点提升（`hoistStatic`）、动态节点标记（Patch Flag），让运行时 diff 更有针对性。
3. **运行时层**：更轻量核心、Tree Shaking 更友好，打包体积通常更小。

在实际项目中，页面复杂度较高（如大表单、数据看板）时，Vue3 的更新效率和首屏体积通常会更优。

**可追问**
- 什么是 Patch Flag？
- Vue3 为什么支持 Fragment？

### 2. `ref` 和 `reactive` 应该怎么选？
**参考答案**
- 原始类型（`string/number/boolean`）优先用 `ref`。
- 复杂对象优先用 `reactive`，代码可读性更好。
- 需要对象“整体替换”时，`ref({})` 更灵活。

补充细节：
- 模板中会自动解包 `ref`，脚本中要通过 `.value`。
- `reactive` 解构后会丢失响应式，建议配合 `toRefs`。

---

### 3. `watch` 和 `watchEffect` 的区别与使用场景？
**参考答案**
- `watch`：明确监听源，支持新旧值比较，适合“有明确依赖”的场景（如监听路由参数触发请求）。
- `watchEffect`：自动收集依赖，立即执行一次，适合“依赖较多且不想手动列出”的场景。

要点：
- 需要拿 `oldValue`、做防抖、做精准监听，优先 `watch`。
- 仅做副作用同步（如根据多个状态更新标题），`watchEffect` 更省代码。

---

### 4. Vue 中如何做组件通信？各方式的边界是什么？
**参考答案**
常见方式：
1. 父子：`props` + `emit`（最推荐，单向数据流清晰）
2. 跨层级：`provide/inject`（适合主题、表单上下文）
3. 全局状态：Pinia（适合用户信息、权限、全局配置）
4. 事件总线（不推荐滥用）：可用于临时解耦，但可维护性较差

设计原则：
- 优先“就近通信”；
- 状态归属明确（谁拥有谁负责）；
- 全局状态不要装业务临时变量。

---

### 5. Pinia 相比 Vuex 的优势是什么？
**参考答案**
- API 更简洁，默认支持 TypeScript 体验更好。
- 去掉冗余的 `mutation` 概念，业务代码更直观。
- 模块化定义天然，组合式 API 风格更统一。
- DevTools 支持完善，调试体验好。

在中大型项目中，Pinia 更利于快速落地和团队协作。

---

### 6. Vue 项目如何做性能优化？
**参考答案（建议按“加载性能 + 渲染性能 + 网络性能”回答）**
1. **加载性能**：
- 路由懒加载、组件按需加载
- 第三方库按需引入
- 开启 gzip/brotli
- 静态资源走 CDN

2. **渲染性能**：
- 使用 `v-memo`、`v-once`（在合适场景）
- 大列表虚拟滚动
- 避免不必要的深层响应式
- 减少频繁创建匿名函数/对象

3. **网络性能**：
- 接口合并与缓存策略（ETag、协商缓存）
- 防抖节流减少无效请求
- 首屏关键请求前置，非关键请求延后

4. **可观测性**：
- 通过 Web Vitals、前端埋点、错误监控做持续优化，而不是“拍脑袋”。

### 7. 如何设计一个通用权限系统（前端视角）？
**参考答案**
常见模型：`RBAC`（角色-权限）。

前端落地：
- 登录后获取权限码集合（如 `user:add`、`order:view`）
- 路由层做动态路由过滤
- 按钮层做 `v-permission` 指令控制
- 页面层做数据级兜底（无权限展示空态）

关键原则：
- 前端权限是“体验控制”，后端权限是“安全边界”。
- 任何接口都必须后端二次鉴权。

---

### 8. 如何封装一个高可用的请求层？
**参考答案**
基于 Axios 二次封装：
- 请求拦截：统一加 token、traceId
- 响应拦截：统一错误码处理、登录态失效处理
- 超时与重试：对幂等接口可安全重试
- 取消重复请求：避免短时间重复点击造成并发脏写
- 统一类型：接口返回结构标准化（`code/message/data`）

加分点：
- 区分业务错误和系统错误
- 上报慢请求和异常到监控平台
- 为接口层写单元测试（mock）

## 二、Java 基础与并发

### 9. `==` 和 `equals` 的区别？
**参考答案**
- `==` 比较引用地址（基本类型比较值）。
- `equals` 比较对象逻辑相等，默认实现仍是地址比较，通常需要重写。

面试注意：
- 重写 `equals` 时通常要同时重写 `hashCode`，否则在 `HashMap/HashSet` 中行为异常。

---

### 10. `HashMap` 底层原理与扩容机制？
**参考答案**
JDK8 `HashMap` 是“数组 + 链表 + 红黑树”结构：
- 键经过 hash 扰动后定位桶位
- 冲突时先链表，链表长度超过阈值（且容量足够）会树化为红黑树
- 负载因子默认 `0.75`，容量阈值达到后触发扩容（通常翻倍）

扩容是高成本操作，设计时可通过预估容量减少扩容次数。

---

### 11. `ArrayList` 和 `LinkedList` 的适用场景？
**参考答案**
- `ArrayList`：随机访问快，适合读多写少。
- `LinkedList`：中间插入/删除理论上更快，但随机访问慢，且节点对象开销大。

实践中：大多数业务场景 `ArrayList` 更常用；`LinkedList` 并不总是更快。

---

### 12. Java 线程池参数怎么设计？
**参考答案**
核心参数：
- `corePoolSize`：核心线程数
- `maximumPoolSize`：最大线程数
- `workQueue`：任务队列
- `keepAliveTime`：非核心线程空闲存活时间
- `RejectedExecutionHandler`：拒绝策略

设计思路：
- CPU 密集型：线程数接近 CPU 核数
- IO 密集型：可适当放大（如 CPU 核数 * 2 ~ *4，需压测验证）
- 明确队列上限，避免 OOM
- 拒绝策略要与业务匹配（丢弃、降级、快速失败）

---

### 13. `synchronized` 和 `ReentrantLock` 的区别？
**参考答案**
- `synchronized`：语法简单，JVM 层实现，自动释放锁。
- `ReentrantLock`：功能更丰富，可中断、可超时、公平锁、支持多个 Condition。

选择建议：
- 普通互斥优先 `synchronized`。
- 需要高级控制（如可中断锁等待）用 `ReentrantLock`。

---

### 14. 说说 Java 内存模型（JMM）和 `volatile`。
**参考答案**
JMM 关注多线程下的**可见性、有序性、原子性**。

`volatile` 保证：
- 可见性：一个线程修改后，其他线程可立即看到
- 有序性：禁止特定重排序

`volatile` 不保证复合操作原子性（如 `count++`）。对复合操作需要 `synchronized` 或原子类（`AtomicInteger`）。

## 三、Spring / Spring Boot

### 15. Spring IOC 和 AOP 的理解？
**参考答案**
- IOC：控制反转，把对象创建与依赖管理交给容器。
- DI：依赖注入是 IOC 的实现方式。
- AOP：面向切面，把日志、事务、鉴权等横切逻辑从业务代码中解耦。

实际收益：减少耦合、增强可测试性和可维护性。

---

### 16. Spring Bean 生命周期简述。
**参考答案**
典型流程：
1. 实例化
2. 属性注入
3. `BeanNameAware`/`BeanFactoryAware` 等回调
4. `BeanPostProcessor` 前置处理
5. 初始化方法（`@PostConstruct` / `InitializingBean`）
6. `BeanPostProcessor` 后置处理
7. 容器关闭时销毁（`@PreDestroy`）

面试可补：AOP 代理对象通常在后处理阶段生成。

---

### 17. Spring 事务失效常见场景？
**参考答案**
典型失效原因：
- 方法不是 `public`
- 同类内部自调用（绕过代理）
- 捕获异常后不抛出，导致事务不回滚
- 数据库引擎不支持事务（如 MyISAM）
- 未配置正确的回滚异常类型

排查建议：
- 看代理是否生效
- 看异常是否传播
- 看事务传播行为是否符合预期

---

### 18. Spring Boot 自动配置原理是什么？
**参考答案**
核心是“约定优于配置”：
- 启动类 `@SpringBootApplication` 包含 `@EnableAutoConfiguration`
- 自动配置类通过 `spring.factories`（新版本机制有演进）被加载
- 借助 `@ConditionalOnXxx` 条件注解决定是否生效

好处：减少样板代码，开箱即用；同时保留手动覆盖能力。

---

### 19. 如何做接口幂等？
**参考答案**
常见策略：
- 前端防重复提交（按钮置灰）
- 后端幂等 token（一次性消费）
- 基于唯一业务键 + 唯一索引
- 分布式场景下结合 Redis 锁/状态机

注意：
- 幂等通常用于“创建类接口、支付回调、消息消费”。
- 要定义清晰的“重复请求返回语义”。

---

### 20. 你如何设计统一异常处理？
**参考答案**
- 使用 `@RestControllerAdvice` + `@ExceptionHandler` 统一拦截
- 统一返回结构：错误码、错误信息、traceId、时间戳
- 区分业务异常与系统异常
- 系统异常不泄露堆栈给前端，但完整记录日志

加分点：
- 错误码分层设计（系统级、模块级）
- 与监控平台联动告警

## 四、MySQL 与缓存

### 21. MySQL 索引原理与最左前缀原则？
**参考答案**
InnoDB 主流索引结构是 B+Tree。

联合索引遵循最左前缀原则，例如 `(a,b,c)` 可命中 `(a)`、`(a,b)`、`(a,b,c)`，一般不能直接命中 `(b,c)`。

索引设计建议：
- 高频过滤、排序、关联字段优先建索引
- 避免过多索引影响写性能
- 定期用 `EXPLAIN` 验证执行计划

---

### 22. 什么情况下会索引失效？
**参考答案**
常见失效场景：
- 对索引列做函数或表达式运算
- 隐式类型转换
- 前导模糊查询（`like '%xx'`）
- `or` 条件不当导致放弃索引
- 数据分布问题导致优化器选择全表扫描

排查方法：`EXPLAIN` + 慢查询日志。

---

### 23. InnoDB 的 MVCC 是什么？解决了什么问题？
**参考答案**
MVCC（多版本并发控制）通过“版本链 + Read View”实现非阻塞读，提升并发性能。

价值：
- 读写不互斥（在很多场景下）
- 降低锁竞争
- 支撑事务隔离级别中的一致性读

---

### 24. Redis 常见问题：缓存穿透、击穿、雪崩如何处理？
**参考答案**
- 缓存穿透：请求不存在的数据
  - 方案：布隆过滤器、空值缓存
- 缓存击穿：热点 key 失效瞬间高并发打 DB
  - 方案：互斥锁、逻辑过期、热点永不过期
- 缓存雪崩：大量 key 同时过期
  - 方案：过期时间随机化、多级缓存、限流降级

---

### 25. 如何保证缓存与数据库一致性？
**参考答案**
经典策略：**旁路缓存（Cache Aside）**。

更新流程建议：
1. 先更新数据库
2. 再删除缓存（而不是更新缓存）

进一步增强：
- 延迟双删（处理并发脏读窗口）
- 订阅 binlog 异步修正
- 对高一致性场景采用读写穿透或消息最终一致方案

## 五、分布式与微服务

### 26. 你理解的微服务拆分原则是什么？
**参考答案**
- 按业务域拆分（DDD 限界上下文思想）
- 高内聚、低耦合
- 以团队边界和发布独立性为导向

避免：
- 过度拆分导致调用链过长
- 共享数据库导致“伪微服务”

---

### 27. 服务间通信如何选型？
**参考答案**
- 同步：HTTP/Feign，简单直接，适合实时查询
- 异步：MQ（Kafka/RabbitMQ），适合削峰解耦、最终一致
- 高性能内部调用可用 gRPC

经验：核心链路尽量短；非核心流程异步化。

---

### 28. 什么是分布式事务？有哪些方案？
**参考答案**
分布式事务是跨服务/跨库场景下的数据一致性问题。

常见方案：
- 2PC（强一致但性能和可用性成本高）
- TCC（业务侵入高，但一致性强）
- Saga（长事务补偿，适合业务流程型）
- 本地消息表 + 最终一致（工程中常用）

面试建议：强调“根据一致性要求、复杂度和吞吐权衡”。

---

### 29. 如何设计一个高可用下单系统？
**参考答案（结构化回答）**
1. 流量入口：网关限流、黑白名单、防刷
2. 业务校验：库存、价格、优惠券、风控
3. 事务处理：本地下单事务 + 事件投递
4. 异步解耦：订单创建后通过 MQ 驱动后续流程
5. 一致性保障：幂等消费、重试机制、死信队列
6. 可观测性：链路追踪、指标告警、异常补偿任务

高并发重点：
- 库存预扣与回补
- 防超卖
- 热点商品隔离

---

### 30. 你如何做限流、降级、熔断？
**参考答案**
- 限流：令牌桶/漏桶，入口按用户/IP/接口维度限流
- 降级：关闭非核心功能，返回兜底数据
- 熔断：依赖服务异常率过高时快速失败，避免雪崩

落地工具：Sentinel、Resilience4j 等。

## 六、前后端协作与安全

### 31. 前后端接口规范如何制定？
**参考答案**
- 使用 OpenAPI/Swagger 管理契约
- 统一响应结构、错误码、分页参数
- 版本策略（`/api/v1`）明确
- 变更流程：先评审再发布，保证兼容

收益：减少联调成本，降低“口头约定”风险。

---

### 32. JWT 鉴权机制及风险点？
**参考答案**
JWT 包含头、载荷、签名；服务端验证签名后信任声明。

风险与防护：
- token 泄露：HTTPS + 短有效期 + 刷新机制
- 无法主动失效：维护黑名单或版本号
- 存储风险：避免暴露在不安全环境（注意 XSS）

实践常用：`AccessToken + RefreshToken` 双令牌。

---

### 33. 常见 Web 安全问题及防护？
**参考答案**
- XSS：输入输出过滤、CSP、避免 `v-html` 直渲染不可信内容
- CSRF：SameSite Cookie、CSRF Token、双重校验
- SQL 注入：预编译参数、最小权限原则
- 文件上传：类型校验、病毒扫描、隔离存储

## 七、测试、部署与可观测性

### 34. 你在项目里如何做测试分层？

### 36. 线上问题如何快速定位？
**参考答案**
排查顺序：
1. 先看监控大盘（错误率、RT、QPS、资源）
2. 再看日志（按 traceId 串联）
3. 复盘变更记录（最近发布/配置变更）
4. 必要时抓取线程栈、慢 SQL、GC 日志

核心是“先止血，再定位，再复盘防复发”。

## 八、系统设计综合题

### 37. 设计一个“用户-角色-权限”管理系统。
**参考答案（简版框架）**
- 表设计：`user`、`role`、`permission`、`user_role`、`role_permission`
- 鉴权流程：登录 -> 拉取权限 -> 缓存 -> 请求时校验

- 扩展：支持数据权限（部门、区域、项目）

### 38. 设计一个短链接系统，核心考虑什么？
**参考答案**
1. 唯一短码生成（哈希/自增转码/号段服务）

## 十、手写与实战高频题

### 43. 手写：实现防抖和节流（Vue 输入搜索场景）
**参考答案（JavaScript）**
```js
export function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

export function throttle(fn, interval = 300) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}
```

### 44. 手写：基于 Redis 的分布式锁要注意什么？
**参考答案**
最小正确集：
- `SET key value NX PX 过期时间`
- value 用唯一标识（如 UUID）
- 释放锁时校验 value（Lua 脚本原子删除）

风险点：
- 业务执行超时导致锁提前过期
- 时钟漂移、主从切换

可提：生产中常用 Redisson，减少自研风险。

### 45. SQL 实战：查询每个部门薪资前 3 的员工。
**参考答案（MySQL 8 窗口函数）**
```sql
SELECT *
FROM (
  SELECT
    e.*,
    ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rn
  FROM employee e
) t
WHERE t.rn <= 3;
```
