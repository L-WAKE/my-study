## 1. 使用方法（面试前 3 小时）

1. 先背第 2 章“通用答题骨架”。
2. 再背第 3-5 章中和你最匹配的 20 题。
3. 最后背第 10 章“项目数字卡片”和第 11 章“反问清单”。

### 1.1 每题记忆法

每题都按这 4 句记忆：

1. 结论：我怎么选。
2. 原理：为什么这样选。
3. 落地：我在项目里怎么做。
4. 结果：数据上有什么变化。

口诀：`结论-原理-落地-数据`。

## 3. 前端深挖题（Vue/Vite/工程化/性能）

## Q1：Vue2 和 Vue3 核心差异是什么？

### 标准回答

- Vue3 的核心变化是响应式从 `Object.defineProperty` 到 `Proxy`，支持更完整的数据拦截。
- 组合式 API 更适合复杂业务逻辑复用。
- TypeScript 体验和 Tree Shaking 更好，大型项目更有优势。

### 追问常见点

- 追问1：为什么说 Composition API 更适合复杂业务？
- 追问2：迁移 Vue2 到 Vue3 最大风险是什么？

### 你的项目落点

- 海外版 SaaS 项目采用 Vue3 + Pinia + TS，把高频业务逻辑抽成 composable，复用率提升到 50%+。

### 记忆锚点

`Proxy + 组合式 + TS + 大型项目`。

## Q2：Vite 为什么比 Webpack 开发体验快？

### 标准回答

- Vite 开发阶段利用原生 ESM，按需加载，不需要全量打包启动。
- 热更新只更新变更模块，反馈快。
- 构建阶段仍可产出高质量包（Rollup 生态）。

### 追问常见点

- 追问1：那 Webpack 什么时候更合适？
- 追问2：你优化过哪些 Vite 配置？

### 你的项目落点

- 在 Vue3 项目中做依赖预构建、路由分包、按需加载，热更新时间做到 200ms 级。

### 记忆锚点

`开发 ESM 快，构建 Rollup 稳`。

## Q3：说一个你做过的前端性能优化闭环。

### 标准回答

- 先做基线：记录首屏、TTI、静态资源体积。
- 再拆瓶颈：路由、组件、图片、接口、缓存。
- 再落手段：懒加载、分包、CDN、并行请求、缓存策略。
- 最后回归验证，确保提升可复现。

### 你的项目落点

- 公寓 SaaS 首屏从 4.2s 到 2.1s，页面交互响应提升约 30%。

### 记忆锚点

`测-拆-改-验`。

## Q4：Pinia 和 Vuex 怎么选？

### 标准回答

- Vue3 新项目优先 Pinia，语法更轻、TS 友好、维护成本低。
- Vue2 历史项目保留 Vuex 更稳，避免迁移风险。
- 本质上选型要看项目阶段和团队熟悉度。

### 你的项目落点

- 旧平台 Vuex 做模块拆分，降低耦合；新平台 Pinia 做领域化 store，提升复用。

## Q5：复杂页面状态管理怎么做？

### 标准回答

- 分层：页面局部状态、业务域状态、全局状态。
- 原则：谁使用谁持有，避免“一切都进全局 store”。
- 通过类型约束和状态快照调试，降低联调成本。

### 易踩坑

- 所有状态进 store，导致维护困难。
- store 里直接写请求逻辑，职责混乱。

## Q6：你如何设计前端请求层？

### 标准回答

- 统一封装：鉴权、超时、重试、错误映射、traceId。
- 支持取消请求、防抖节流、重复请求去重。
- 对关键接口定义类型和转换层，防止字段漂移。

### 追问常见点

- 为什么要加转换层？
- 请求重试怎么避免雪崩？

## Q7：前端权限控制怎么落地？

### 标准回答

- 三层控制：路由级、页面级、按钮级。
- 权限码由后端下发，前端仅做展示和交互控制。
- 关键安全校验必须在后端完成。

### 记忆锚点

`前端控展示，后端控安全`。

## Q8：你如何做组件库设计？

### 标准回答

- 先识别高频场景，组件 API 追求最小闭包。
- 设计 token 统一视觉与间距。
- 配套文档和示例，降低团队接入成本。

### 你的项目落点

- 跨端项目封装通用组件（弹窗、JSON 表单、筛选等），提升研发效率 50%+。

## Q9：Uniapp 多端兼容的核心策略是什么？

### 标准回答

- 建立“能力分层”：通用层 + 端适配层。
- 把平台差异收敛在适配层，业务层不感知端差异。
- 建立多端回归清单，重点关注样式、权限、API 差异。

## Q10：线上白屏如何快速排查？

### 标准回答

- 先看资源加载（404、跨域、缓存）。
- 再看运行时错误（JS 报错、polyfill 缺失）。
- 再看鉴权和路由重定向是否死循环。
- 最后看接口阻塞和容器环境差异。

## 4. 后端深挖题（Java/Spring Boot/MySQL/Redis）

## Q11：Spring Boot 自动配置原理是什么？

### 标准回答

- 基于自动配置机制，根据类路径和配置条件装配 Bean。
- 核心是“约定优于配置”，减少样板代码。
- 可通过条件注解和排除项实现精细控制。

### 追问常见点

- 你如何排查某个自动配置为什么生效/不生效？

## Q12：事务失效常见原因有哪些？

### 标准回答

- 同类内部调用绕过代理。
- 方法不是 public。
- 异常被吞或异常类型不触发回滚。
- 传播行为设置不当。

### 记忆锚点

`代理、可见性、异常、传播`。

## Q13：MySQL 索引优化你一般怎么做？

### 标准回答

- 先用慢日志定位。
- 再用 EXPLAIN 看执行计划（type、rows、extra）。
- 结合业务查询模式做联合索引和 SQL 改写。

### 你的项目落点

- 在部分后端联调中做过慢查询优化和缓存策略，减少接口响应时间。

## Q14：联合索引最左匹配怎么理解？

### 标准回答

- 联合索引按从左到右匹配。
- 跳过前导列会影响索引使用。
- 范围查询之后的列利用率下降。

## Q15：Redis 缓存穿透、击穿、雪崩怎么处理？

### 标准回答

- 穿透：布隆过滤器 + 空值缓存。
- 击穿：热点 key 互斥锁 + 逻辑过期。
- 雪崩：过期时间打散 + 限流 + 降级 + 预热。

## Q16：分布式锁怎么保证不误删？

### 标准回答

- 加锁用 `SET NX EX`，value 为唯一标识。
- 解锁用 Lua 脚本先比对 value 再删除。
- 防止锁超时导致误删其他线程的锁。

## Q17：接口幂等怎么做？

### 标准回答

- 前端提交幂等 token。
- 后端落库唯一约束或去重表。
- 对支付/下单等关键链路必须落地。

## Q18：你如何设计统一错误码？

### 标准回答

- 分层：系统级、业务级、鉴权级。
- 响应结构统一：code/message/data/traceId。
- 错误码语义前后端约定，减少扯皮。

## Q19：JWT 的优势和风险？

### 标准回答

- 优势：无状态、扩展性好。
- 风险：泄露后难立即失效、体积大、续期管理复杂。
- 实践：短有效期 + 刷新机制 + 黑名单。

## Q20：限流算法你怎么选？

### 标准回答

- 固定窗口简单但可能突刺。
- 滑动窗口更平滑。
- 令牌桶适合控制平均速率并允许突发，业务里更常用。

### 标准回答
